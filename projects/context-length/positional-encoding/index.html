Deep Learning Context-Length Series · Part 1

Sinusoidal positional encoding, built from nothing

Self-attention reads a sentence as an unordered bag of words. Before it can matter that "dog bites man" is not "man bites dog", we have to hand each token a sense of where it sits. This is the first, smallest, most elegant answer to that problem, a bank of sine waves, explained from the ground up, with everything here to touch.

This is Part 1 of a series on how language-model context windows grew from 512 tokens in the original Transformer to millions. It stands entirely on its own. Later parts build learned, relative, and rotary encodings on top of exactly the idea developed here.
The positional-encoding matrix: one row per position, one column per dimension. Every row is a different fingerprint. We will earn every stripe of this picture.
The problem

Attention cannot see order

Let me start with the single fact that makes everything after it necessary. The attention mechanism, on its own, has no idea what order its inputs came in.

Here is the whole thing in slow motion. Self-attention takes a set of token vectors and, for each token, produces a new vector that is a weighted sum of all the other tokens' vectors. The weights come from how similar the tokens are to each other, a dot product between a "query" and a "key". Anyone who has read the companion piece on attention will recognise the same machinery; if not, the only thing to hold onto is this: the output for a token is a sum, and a sum does not care about the order of the things being summed.

2 + 5 + 9 and 9 + 2 + 5 are the same number. In exactly the same way, if we take the words of a sentence, shuffle them, and feed them to raw attention, every token gets back the identical vector it would have gotten before, just sitting in a different slot. The math is permutation-equivariant: permute the input, and the output is simply permuted the same way, never actually changed. To attention, "dog bites man" and "man bites dog" are the same bag of three words.

Every arrangement is, to the model, the exact same input. That is the bug we spend the rest of this page fixing.

The one requirement

We need to stamp each position with a signal, a vector, that is unique to that position and that we add into the token's embedding before attention ever runs. Then two identical words in different places arrive at attention already looking different. That signal is a positional encoding.

So the task is narrow and concrete: invent a function that turns a position, an integer like 0, 1, 2, 3, …, into a vector of d numbers, where d is the width of the model's embeddings (512 in the original paper). Every position gets its own vector; we add it onto the word's embedding; attention can finally tell the front of the sentence from the back. Simple to state. The rest of this page is about doing it well, because the obvious attempts fail in instructive ways.

False starts

The obvious ideas, and why they break

Before the clever answer, it is worth feeling the two naive answers fail, because each failure is a requirement in disguise.

Attempt 1: just add the position number

Remember the goal from a moment ago: turn a position into a vector of d numbers and add it, slot by slot, onto the word's embedding. The laziest way to do that is to skip building a real vector and simply take the raw position number and add it to every slot. So the token at position 0 gets 0 added to each of its numbers, position 1 gets 1 added to each, position 1000 gets 1000 added to each.

Make it concrete. Suppose the word "cat" has the embedding [0.2, -0.5, 0.1, …], every number sitting roughly between -1 and 1, as embeddings do. At position 1000 it becomes [1000.2, 999.5, 1000.1, …]. The original values, the ones that actually carried the meaning of "cat", are now rounding error next to a giant 1000. We have not tagged the word with its position; we have erased the word and kept only the position.

And it only gets worse further into the text, because position is unbounded: a longer document just means larger and larger numbers with no ceiling. (Tacking the position on as one extra number, concatenating it rather than adding, hits the same wall from the other side: the value still has no upper limit, and now a single lonely slot has to carry all of the position information.) So the first requirement writes itself: whatever we add has to stay small and bounded, no matter how long the sequence.

Attempt 2: squash the position into [0, 1]

Fine, bound it. Divide the position by the length of the sequence before adding it, so the first token contributes 0.0, the last contributes 1.0, and every value sits politely in between. Bounded at last. But now a subtler bug appears, and the widget below is the fastest way to feel it.

"Third word in" should mean the same thing in a tweet and in an essay. Here it does not: the value of position 3, and the distance to position 4, both depend on how long the sentence happens to be. The model can never learn a stable notion of "three tokens apart".

Between these two failures we have quietly written a specification. A good positional encoding must be:

  • Bounded: values stay in a small range no matter the position (Attempt 1's lesson).
  • Consistent: position 3 means the same thing, and the step from 3 to 4 is the same size, regardless of total length (Attempt 2's lesson).
  • Unique: no two positions share the same encoding, or the model literally cannot tell them apart.
  • Extendable: it should keep producing sensible values for positions longer than anything seen in training, so a model can read a document longer than its training examples.
  • Relative-friendly: ideally it makes "how far apart are these two tokens" easy to compute, because that is what attention actually wants to know. (We will see this fall out for free, and it is the most beautiful part.)

Here is the tension that makes this a real puzzle. "Bounded" pushes us toward something that repeats, a wave that cycles between fixed limits. But anything that repeats is, by definition, not unique: a plain sine wave gives position 0 and position $2\pi$ the exact same value. How do we build something bounded out of repeating parts that is nonetheless unique over a huge range of positions? The answer is an idea we already understand from a completely different context.

The key intuition

We already know the trick: it's binary counting

How do we represent every integer uniquely using only components that each just flip back and forth between two bounded values? We have all done it since grade school. It is binary.

Count in binary and watch the columns. The rightmost bit flips every single step: 0,1,0,1,0,1…. The next bit flips half as often, every two steps: 0,0,1,1,0,0,1,1…. The next, every four steps. Each column is a bounded, repeating signal, it only ever shows 0 or 1, yet by running the columns at different frequencies and reading them together, every number gets a unique pattern. Low bits change fast and capture the fine detail; high bits change slowly and capture the coarse, large-scale position.

Binary counting is positional encoding with square waves different frequencies

The counter ticks upward. Each column is one bit; notice how much slower each bit flips than the one to its right, every column halves the frequency. Then flip on "smooth" to replace each square wave with a sine wave of the same frequency. That single change is the leap to sinusoidal encoding.

counter 0
bit 0 flips every 1 step
bit 1 every 2
bit 2 every 4
bit 3 every 8

Two facts to carry forward: (1) uniqueness comes from combining many frequencies, not from any single one; (2) each frequency is a fixed fraction of the one below it, a geometric ladder of rates.

Why not literally use binary bits, then? Because they are jagged. Those hard 0→1 jumps are discontinuous, a tiny change in position can flip a bit completely, and neural networks learn best from smooth signals where a small change in the input makes a small, predictable change in the output. So we keep the brilliant part of binary (a geometric ladder of frequencies, read together) and throw away the jagged part. The smooth, continuous version of a signal that oscillates between two bounded values is exactly a sine wave. Toggle "smooth" above and we have, essentially, invented the encoding.

Sinusoidal positional encoding is binary counting with the corners rounded off: a stack of sine and cosine waves whose frequencies form a geometric ladder from fast to slow.
The definition

The formula, one symbol at a time

Now the actual equation from the paper. It looks dense; it is really just "sine and cosine waves at a geometric ladder of frequencies", which we already have in hand.

$$ PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{\,2i/d}}\right) \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{\,2i/d}}\right) $$

Every letter, slowly:

  • pos: the position of the token in the sequence: 0 for the first token, 1 for the second, and so on. This is the input to the encoding.
  • d: the dimension of the encoding vector, the same width as the word embeddings so we can add them. In the paper, d = 512.
  • i: indexes the pairs of dimensions. It runs from 0 up to d/2 - 1. Each value of i owns two slots in the output vector: an even slot (2i) filled by a sine, and the next odd slot ($2i{+}1$) filled by a cosine at the same frequency.
  • 10000: a hand-chosen constant that sets how slow the slowest wave gets. It stretches the wavelengths across a huge range so the ladder spans from very fast to very slow. More on why 10000 below.

The whole engine is the denominator $10000^{2i/d}$, which sets the frequency of pair i. When i = 0 the denominator is $10000^0 = 1$, so the wave is $\sin(pos)$, the fastest wave, our "bit 0". As i climbs toward d/2, the exponent climbs toward 1, the denominator climbs toward 10000, and the argument pos/10000 crawls, the slowest wave, our high bit. In between, the frequencies are spaced geometrically, each a fixed ratio slower than the last. That is the binary ladder, made continuous.

Equivalently, in terms of wavelength, how many positions it takes a wave to complete one full cycle, pair i has wavelength $2\pi \cdot 10000^{2i/d}$. The fast waves cycle every $2\pi \approx 6.28$ positions; the slow ones take tens of thousands of positions to come around once. A given position lands at a different phase on every one of these waves, and the full collection of those phases is its encoding vector.

Why a sine and a cosine?

One detail of the formula is worth flagging now, though its full answer comes a little later. Each frequency appears twice: a sine in one slot, a cosine in the next. This is not for uniqueness. Many plain sine waves at different wavelengths could already tell every position apart, which is just the binary-ladder idea again. The pairing buys something else, a property about the distance between two positions, and it is far easier to see once we can watch two encodings being compared. We come back to it, and it turns out to be the whole reason sinusoids are used, in the section on relative position.

See it move

The ladder of waves, and reading off a vector

Time to make the formula concrete. Here is the ladder of waves itself, the fast ones up top, the slow ones at the bottom, with a movable position line. Where the line crosses each wave, we sample a value. Stack those samples and we have the positional encoding vector for that position.

The frequency ladder drag the position line

Each row is one pair of dimensions: a sine and its cosine partner at the same frequency. Top rows are fast (low i), bottom rows are slow (high i). The dots where the vertical line meets each wave are the numbers that make up the encoding vector, listed with their values in the strip on the right.

Slide the position slowly. The top wave races through whole cycles while the bottom wave barely stirs, fast bits for fine detail, slow bits for coarse location, exactly like the binary counter. Drop the base constant and watch the slow waves speed up, cramming the ladder into a smaller range of frequencies.

Notice what "unique" looks like here. Any single wave repeats, the top one returns to the same height every few positions, so on its own it could never distinguish, say, position 3 from position 3-plus-one-wavelength. But the combination across all the rows never repeats over any range that matters in practice: for two positions to collide, they would have to line up simultaneously on the fast wave and the medium waves and the glacial bottom wave, and the geometric spacing of frequencies makes that astronomically far away. Many bounded, repeating parts; one unique whole. That is the binary trick, still doing its job.

The payoff

Why the pairing matters: distance, not position

Here is the property that makes the sine-and-cosine pairing worth it, the one flagged back at the formula. Attention never looks at a positional vector on its own; it always compares two of them with a dot product. So the question that decides everything is simple: what does that dot product depend on?

Recall that the encoding vector is a stack of (sine, cosine) pairs, one pair per frequency. A dot product is the sum of the products of matching entries, so comparing position m with position n splits into one contribution per frequency. Take a single frequency $\omega$: its pair holds $\big(\sin(\omega m),\, \cos(\omega m)\big)$ and $\big(\sin(\omega n),\, \cos(\omega n)\big)$, so it adds one sine-times-sine plus one cosine-times-cosine, which a standard identity collapses to a single term:

$$ \sin(\omega m)\,\sin(\omega n) + \cos(\omega m)\,\cos(\omega n) \;=\; \cos\!\big(\omega\,(m - n)\big) $$

Only m - n survives: the gap between the two positions. Every frequency's pair behaves the same way, so the dot product of the two full vectors is just the sum of these terms:

$$ PE(m)\cdot PE(n) \;=\; \sum_{i} \cos\!\big(\omega_i\,(m - n)\big) $$

The right-hand side has no absolute position in it, only the gap m - n. Two tokens a fixed distance apart give the same positional similarity wherever they sit in the text, and that is exactly what a Transformer wants: attention can learn "attend one token back" or "attend fifty tokens back" once and reuse it at every position, instead of memorising a separate relationship for every absolute pair.

It is not a perfect distance signal, though. Because that sum runs over many cosines at different frequencies, it does not fall off cleanly as the gap grows; it ripples, so two different gaps can end up with the same similarity. That rippling is a genuine limitation of raw sinusoidal encodings, and one of the reasons the later positional schemes in this series were invented.

Loose ends

Two last questions, and the door to the rest of the series

Why add it to the embedding instead of gluing it on the side?

A fair objection: adding the positional vector to the word vector seems to corrupt the word. Why not concatenate, keep the word in its own slots and the position in separate slots? The practical answer is cost and freedom: concatenation would widen every vector and every matrix in the model. Addition keeps the width at d, and in a space of hundreds of dimensions there is ample room for the network to learn to keep the two signals separable, to read "which word" and "where" out of the same summed vector using different learned projections. In practice it simply works, and the whole Transformer is built on the assumption that it does.

Why the number 10000?

It sets the wavelength of the slowest wave, and therefore the longest distance the encoding can represent before its slowest component starts to wrap around. 10000 was chosen to comfortably cover the sequence lengths of the day, hundreds of tokens, with headroom. It is not sacred; it is a knob, as the base slider in the widgets above showed. Hold onto that fact, because it is the hinge for everything that follows.

The hook to context length

Because these are real sine waves, the formula happily produces a vector for position 1{,}000{,}000 even if the model only ever trained on positions up to 512. In principle it extrapolates to any length for free. In practice it mostly does not, a model trained on short sequences has never seen the particular phase combinations that long positions produce, and it stumbles. That gap between "the encoding is defined everywhere" and "the model actually behaves well out there" is the entire drama of the context-length story.

The next parts of this series are, in a real sense, sustained attempts to fix the failure this section just named. Learned positional embeddings drop the formula and let the model memorise a vector per position, flexible, but with a hard ceiling at the longest position ever trained. Relative schemes encode the offset k directly rather than absolute positions, leaning hard on the same translation-invariance the dot product showed us above. And rotary embeddings (RoPE), instead of adding a positional signal at all, rotate the query and key vectors themselves by an angle set by the position, which turns out to extrapolate far better and is what most modern long-context models actually use. Every one of them is a direct descendant of the ladder of sine waves we just built by hand.

Start from "attention can't see order", demand bounded-consistent-unique, borrow the geometric frequency ladder from binary, round off the corners into sines, and pair each sine with a cosine so a dot product depends only on the distance between positions. That is the whole idea, and the seed of every positional scheme that carried context windows from 512 to millions.
